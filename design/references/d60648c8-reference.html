Meridian

The reference page for our web design system. Every value on this page is read from the same token files the build pipeline consumes, so what you see here is what ships.

Colour

Two layers. The palette is the raw ramp and shifts between appearances on its own. Semantic roles name a job rather than a hue — build against those, so a brand change is one edit in one file.

Typography

Eleven styles, borrowed from the platform text styles. A style is a bundle: size, line height, tracking and weight travel together. Pick the style whose job matches; never set a size on its own.

Space

A 4pt grid. Reach for the step by name — --ds-spacing-4, not 16px — so the rhythm survives a scale change.

Shape

Radius encodes size, not decoration. A control and the card containing it should not share a radius — the outer shape is always the rounder one.

Elevation

Five levels, each tied to a behaviour rather than a look. If two surfaces sit at the same level, they are peers and neither should cast a shadow over the other.

Controls

One action per button, named for what happens when it is pressed. Filled marks the single primary action on a screen; everything else steps down from there.

Motion

Motion answers an action and shows what changed. Nothing animates on load. Every duration collapses to 1ms when the visitor asks for reduced motion, so no component needs to handle that itself.

Meridian Design System v1.0.0. Generated from tokens.json by build_tokens.py. This page links tokens.css directly and defines no colour, size or timing of its own.

Structure and conventions follow Apple's published Human Interface Guidelines — the platform type scale, the 4pt grid, semantic label and fill roles, and the 44px touch target. It ships no Apple fonts, icons or other assets; the font stack asks the operating system for its own UI face and falls back on every other platform.

Replace the Meridian name and the accent role with your own before rollout. Nothing else needs to change.
